## How to use this matrix

1. Before starting any implementation prompt, identify which rows apply to its scope.
2. Read the "Authoritative artifact" column's documents/files in full before writing code — do not infer contract details from this summary table alone.
3. If an implementation prompt discovers the contract is insufficient (missing a needed field, ambiguous behavior), it must not invent a divergent local answer — it should implement the closest compatible interpretation, flag the gap explicitly in its completion report as an "unresolved architectural issue," and a future architecture revision resolves it here.
4. QA consumers use this matrix to build a contract-test inventory ensuring every row has at least one automated test validating conformance, not just manual review.
